# ochrepad

A Notepad++-style text editor in Rust on egui/eframe 0.36. 0.1.0 covered the original plan (`docs/design/PLAN_v0.1.0.md`, M0–M13); 0.2.0 added folding, word wrap, the document map, Find All and Find in Files, the folder workspace and an editable compare view (`docs/design/PLAN_v0.2.0.md`, N1–N10). 0.3.0 (`docs/design/PLAN_v0.3.0.md`, P1–P9; unreleased) adds editing basics, per-document indentation/EOL/encoding, zoom and Show Symbol, text tools, undo across sessions, log tools and the viewer for huge files. The plans are kept for their rationale; this file is the current guide. Work now is maintenance, polish and new features.

## Commands

```sh
cargo build --release                         # target/release/ochrepad(.exe)
cargo test --workspace                        # everything (~1 min in debug; props + incremental are the slow ones)
cargo fmt
cargo clippy --all-targets -- -D warnings
UPDATE_SNAPSHOTS=1 cargo test -p ochrepad --test visual --test compare_ui --test find_ui --test preview
cargo run --release -p ochrepad --example gen_perf_fixtures   # 50k-line .rs + 100 MB .txt in target/perf-fixtures
cargo run --release -p ochrepad --example gen_perf_fixtures -- target/perf-fixtures --log 1024   # a 1 GB log (any size; delete after)
cargo run --release -p ochrepad -- --bench --viewer <file>    # the viewer: first frame, index time, scrolling
cargo run --release -p ochrepad -- --bench <file>             # scroll/typing frame times, prints a table
cargo run --release -p ochrepad --example find_bench -- <file>
cargo run --release -p ochrepad --example diff_bench -- <file>
cargo run -p ochrepad --features dev-inspect                  # egui inspection protocol, with EGUI_INSPECTION=1
```

A change is done when fmt, clippy (`-D warnings`) and `cargo test --workspace` pass. Commit at green; the user pushes.

Supported platforms are Windows and Linux (x86-64); macOS is not supported. CI (`.github/workflows/ci.yml`) runs the same checks on both for pull requests and pushes to `main`. Failed snapshot tests upload their `.new.png`/`.diff.png` images as an artifact. Linux is only exercised there, so check that run after platform-sensitive changes (paths, fonts, file watching, rendering). To catch Linux compile errors locally first: `cargo clippy --workspace --all-targets --target x86_64-unknown-linux-gnu -- -D warnings` (the target is installed). Actions are pinned to commit SHAs with the tag in a comment; when updating one, pick a release at least two weeks old.

The release exe is locked while it runs, so `cargo build --release` fails with "Access is denied" if the user has ochrepad open. That is not a build error.

## Releasing

`.github/workflows/release.yml` runs when a `v*` tag is pushed. It checks the tag matches the version in the root `Cargo.toml`, builds `ochrepad-vX.Y.Z-windows-x86_64.zip` (windows-latest) and `ochrepad-vX.Y.Z-linux-x86_64.tar.gz` (ubuntu-22.04, for older glibc), each with README, LICENSE and CHANGELOG; attests their build provenance; and creates a **draft** GitHub release with `SHA256SUMS.txt` and the version's `CHANGELOG.md` section as notes. Steps for a release:

1. The four crates share one version. Set it in the root `Cargo.toml` twice: `[workspace.package] version`, and the `=X.Y.Z` pins on the internal crates in `[workspace.dependencies]`. Then run `cargo check` to update `Cargo.lock`.
2. In `CHANGELOG.md`, move the entries from `[Unreleased]` into a `## [X.Y.Z] - YYYY-MM-DD` section, and add its compare link at the bottom.
3. Commit, merge to `main`, then `git tag vX.Y.Z && git push origin vX.Y.Z` (the user pushes).
4. Check the draft release's files and notes on GitHub, then publish it.
5. Publish to crates.io from the tagged commit: `cargo publish --workspace --dry-run`, then `cargo publish --workspace` (the user runs it). This publishes the internal crates first. A version can be yanked but never replaced, so check the dry run.

Package metadata (description, license, repository, keywords) lives in `[workspace.package]` and each crate's `[package]`. The internal crates have to be on crates.io for `cargo install ochrepad` to work. Their descriptions say they have no stable API.

Keep `CHANGELOG.md`'s `[Unreleased]` section up to date as user-visible changes land; it is written for people downloading the release. Releases are unsigned (see Open ideas).

## Architecture rules

These are load-bearing. Check with the user before changing any of them.

- **Byte offsets are the canonical position.** Every stored position is a `ByteOffset` into the UTF-8 text, on a char boundary. `CharIdx`, `LineCol` and `VisualCol` are newtypes derived on demand in `core::position`. The cursor moves by grapheme cluster.
- **Selections are always a `SelectionSet`**: non-empty, sorted, non-overlapping, with a primary index. A column selection is a set (one selection per line) plus an optional `Rectangle`. Any action that is not column-aware clears the rectangle.
- **Two-layer edits.** An `Action` is the user's intent (serde-serializable; key bindings and macros use Actions). It resolves to a `Transaction` (a `ChangeSet` plus selections before and after); undo stores Transactions. **`Editor::apply` is the only path that mutates a rope** (one exception: `Editor::append_unrecorded`, follow mode's appends, which are not undo steps). It pushes undo, maps other views' selections with `ChangeSet::map_position`, records the `LineEdit`s for the highlighter, bumps the revision and records macros.
- Dirty means `revision != saved_revision`, so undoing back to the save makes the tab clean again. Typing coalesces into one undo step; macro playback, Replace All and every transform are one step each.
- **Line endings are LF inside.** `fileio` normalizes on load and restores on save. Nothing outside `fileio` looks at `\r`, except where text arrives from elsewhere: the text tools' decoders normalize what they decode, and the viewer's raw byte search (`Searcher::new_raw`) treats CR LF and CR as line breaks in an unnormalized file. Mixed endings are saved as the dominant one, with a status-bar note.
- **One layout for paint and hit test.** `LineLayout` holds the x of every grapheme boundary; painting, carets, selections and clicks all use it (the compare view's sides are editor widgets). Never compute x positions in a second place. Monospace grid: x = `VisualCol × cell width`; wide and fallback glyphs are placed individually on the grid, and emoji are clipped to their cells.
- **Line ↔ row mapping goes through `core::display::DisplayMap`.** Rows are addressed relative to their line (`RowPos { line, sub }`); there is no global row index, so nothing has to wrap a whole file. The editor widget scrolls, paints and hit-tests through it, and vertical motions (`Up`/`Down`/`PageUp`/`PageDown`, add cursor above/below) resolve through it in core, so macros move by rows in whatever view plays them. Folded lines have no rows; with word wrap (`View::wrap_cols`, set by the widget from the pane width) a line has one row per wrapped piece, cached per view and revalidated by line text. A position at a wrap point shows at the start of the next row, so `row_end` of a wrapping row is one grapheme before it (no caret affinity). A compare view's sides are auxiliary editor views (`Editor::add_aux_view`, left out of `views_of`) with `View::padding`: blank rows before lines (and after the last), from `LineDiff::padding`; carets skip them, and folds and wrap are off in a padded view.
- The editor widget does its own virtual scrolling (top row as `first_line` + `first_sub`, plus a fraction; the scrollbar works in visible lines). Do not use egui `ScrollArea` for it: f32 pixel offsets lose precision in big files.

## Working rules

- `ochrepad-core` stays free of egui and of filesystem access. If you need either there, the design is wrong; ask.
- No `unwrap()`/`expect()` on user data (file contents, patterns, config, session). Errors surface in the UI (`self.message` modal or inline).
- User files are written only by atomic replace, and only from the worker thread. Never block a frame on I/O.
- Dependencies are pinned exactly (`"=x.y.z"`). Ask before adding one. Approved additions since the plan: `image` (jpeg, webp), `winresource` (Windows build-dependency), `resvg` (no default features), `ignore` (fileio, for `.gitignore`), `md-5`, `sha1`, `sha2` (core, for the text tools' hashes and the undo history's text hash; `default-features = false`), `memmap2`, `memchr` (fileio, the viewer). All egui-ecosystem crates must stay on the same egui minor version (egui/eframe/egui_kittest 0.36, egui_dock 0.21, egui_commonmark 0.25).
- egui 0.36 is Ui-first: `App::ui(&mut self, ui, frame)`, and panels show inside a `Ui`. Online examples are often older; check the crate source in `~/.cargo/registry` rather than memory.
- Match Notepad++ behaviour where it has an opinion (shortcuts, autosave-as-backup, exit without prompting when backups are on).
- User documentation lives in `docs/` (index: `docs/README.md`; the README links each page). Update the page when you change the behaviour it describes. `crates/ochrepad/tests/docs.rs` fails when a new `Action` variant has no example in `docs/keymap.md`, or when a JSON example in the docs stops parsing.

## Settled decisions

- **Fonts**: a CJK fallback font is loaded from the system (else tofu stays on the grid). Menus use the system UI font (Segoe UI on Windows; a list of common sans fonts on Linux). The editor font is a choice among installed monospace fonts, or the built-in Hack.
- **Folder workspace**: one root folder in a left `Panel` outside the dock. Folders are listed lazily on the `fileio` lister thread; ignored entries (and `.git`) are hidden unless Show Ignored Files. The `notify` watcher also watches the root and expanded folders, non-recursively, and the tree relists a changed folder after 0.2 s. Create and rename go through the worker and refuse to overwrite; a rename updates open buffers' paths. No delete. Root, expanded folders and Show Ignored are in the session; Ctrl+Shift+E toggles the sidebar.
- **Document map** (`doc_map.rs`): a 100 px strip inside each editor, 2 px per row and 1 px per cell, drawn as one `Mesh` of coloured blocks per run of non-blank text (highlight colour at reduced alpha). It shows the editor's rows (folds and wrap apply), scrolls in proportion when the document is taller than the strip, and its marker drags like a scrollbar. Per-line ink is cached and revalidated by line text and span pointer. Hidden when fewer than 40 text columns would fit beside it. Costs about 0.3–0.5 ms a frame while scrolling.
- **Word wrap**: one global setting (`AppSettings::word_wrap`), wrapping at the pane edge after whitespace, continuation rows indented like the line (at most half the width). `LineLayout` stays per line; a wrapped row paints its slice, clipped, shifted by `row_x0`. Home/End are bound to `RowHome`/`RowEnd`, which equal `Home`/`LineEnd` without wrap. The scrollbar counts visible lines, not rows.
- **Folding** (`core::fold`): regions come from indentation (a line whose next non-blank line is indented deeper), or headings for Markdown (`Buffer::fold_strategy`, set from the language in `highlight.rs`). No whole-document scan except Fold All and the level commands. Folds are per view, stored as byte ranges, and changed only through `Editor`: an edit that touches a fold's hidden text drops it, and after every action any fold hiding a caret is unfolded (`sync_folds`). Fold actions are not undo steps and are not recorded in macros. Session tabs keep folded header lines.
- **Comments**: `Buffer::comments` (a `CommentSyntax`) is set from the language by `highlight.rs`, from the table in `ochrepad-syntax/src/comments.rs` (two-face syntaxes carry no comment metadata). A test checks every entry names a real language. Ctrl+/ toggles line comments (block comments for block-only languages), Ctrl+Shift+/ block comments.
- **Regex**: Rust `regex` syntax through `regex-cursor` (no lookaround or backreferences), documented in `docs/find-and-replace.md`. A `fancy-regex` fallback can be added behind the `Matcher` trait.
- **Look** (`theme.rs`): warm charcoal and paper palettes with ochre `#CC7722` accents (caret, selection, focus, current line number, active tab line, hovered split divider). Find matches are teal and changed compare rows blue, so they never look like the selection. The tab bar is 36 px tall (`theme::BAR_H`), and the sidebar's header matches it; margins and gaps use `theme::space` (4, 8, 12, 16).
- **Logo**: `logo.rs` is dependency-free and shared by the window icon and `build.rs` (included by path), which generates the `.ico` for `winresource`. A failed embed is a warning, not an error.
- **Markdown preview images load only from this machine** (`safe_images.rs`, from a security review). `LocalFilesOnly` sits above egui_extras' loaders and refuses `file://` URIs that are not on a local drive, because UNC paths would send NTLM credentials. `SafeSvgLoader` replaces egui_extras' SVG loader with an `<image>` resolver that reads only files inside the SVG's folder. `SafeRasterLoader` decodes PNG/JPEG/WebP/BMP with `image::Limits` and shrinks anything over `max_texture_side` (a larger texture crashes wgpu); SVGs are clamped the same way; `LocalFilesOnly` also refuses non-regular files and files over 32 MB, and (Windows) paths through a link to a network path. Install order matters: egui asks the newest loader first, and `install()` draws an empty `CommonMarkViewer` first so egui_extras' loaders go in below the guards. egui names frames of possibly animated images `uri#0`; strip that before reading bytes.
- **Preview links** (`preview.rs` `classify_link`): only `http`, `https` and `mailto` reach the OS; file links (and scheme-less paths, resolved against the document's folder) open in ochrepad; everything else is refused with a status note. egui_commonmark does not prefix links with the base URI, only images.
- **Mouse**: a double-click on an empty tab bar opens a new tab in that pane. A click on a line number selects the line; drag and Shift+click extend by lines. Hovering another menu title switches menus while one is open (egui's `MenuBar` does not do this; see `switch_menu_on_hover`).
- **Release builds** use the Windows GUI subsystem (no console), so `--bench` output must be redirected to a file.
- **Indentation is per buffer**: `Buffer::indent` (`use_spaces`, `width`; the width is also the tab width). Anything that computes visual columns asks the buffer, never the settings. Opening a file runs `core::indent::detect`; `indent_set` marks a buffer whose indentation was detected or chosen, and preference changes only reach buffers without it. Line ending and encoding stay in `FileMeta` and change only through the status bar menus.
- **Zoom and Show Symbol**: `AppSettings::zoom` (percent, `ZOOM_LEVELS`) scales the editor font only; egui's own Ctrl+plus/minus window zoom is turned off in `apply_settings`. Ctrl+wheel over an editor leaves zoom steps in egui temp data (`editor_view::take_zoom_steps`) for the app. The app hands every editor (and the compare view's sides) an `editor_view::Look`: font size, `Symbols` and the edge column. Special characters keep the one cell `grapheme_width` gives them; their boxes are labelled only when the label is legible (zoomed in), otherwise the tooltip names them. Control characters are boxed even with Show Symbol off (Notepad++ does the same).
- **Robustness** (from the 0.3.0 security review): `fileio::read_file` opens first and then checks (regular files only, at most `MAX_LOAD_SIZE`, `O_NONBLOCK` on Linux so a FIFO cannot block). User files are saved with `write_user_file` (new files get normal permissions; Windows keeps `Zone.Identifier`); ochrepad's own files use `write_atomic` (0600 when new). Snapshot ids are checked (`is_snapshot_id`). Lines over `ochrepad_syntax::MAX_HIGHLIGHT_LINE` bytes are not highlighted. `LineLayout` stores printable-ASCII stretches as one run, and `paint_line_text` lays out only the visible part of a run. `main.rs` catches a panic in `show`, runs `emergency_backup`, shows a message and re-panics.
- **Bookmarks** (`core::bookmarks`): line numbers in the `Buffer` (per document, as Scintilla's markers), not byte offsets: `apply_changes` maps them with each edit's lines, as Scintilla does (text inserted at a marked line's start pushes the mark down; a mark whose line break before it is deleted joins the line before; marks inside a replaced block keep their line within it). Not undo steps; the bookmark actions are recorded in macros. The number of a marked line is drawn on an accent tag in the gutter. Paste to (Replace) Bookmarked Lines sets a flag in the widget so the next `Event::Paste` (from `RequestPaste`) goes to `Action::ReplaceBookmarkedLines`. The session keeps them per buffer.
- **Right-click** in the editor moves the caret to the click unless it is on the selection (Scintilla's behaviour), and `editor_menu.rs` shows the menu on the response; `EditorViewState::context_line` is the line clicked.
- **Filter view** (PLAN_v0.3.0 P6): the filter's hidden lines live in the view's `FoldSet` (merged with fold regions into the one `hidden` list the display map reads), as line ranges shifted by the `LineEdit`s `apply_changes` returns; lines an edit touches show, and `sync_folds` shows a line a caret lands on. `Editor::set_filter` moves carets off hidden lines (and keeps the caret's line when nothing matches, so a view always has a row). The app (`filter_bar.rs`) searches on a thread over a rope clone and re-filters after a pause.
- **Log tools in the viewer** (P8): `viewer::Shown` is `All`, `Lines` (show matching) or `AllExcept { excluded, decided }` (hide matching, with only lines before `decided` known while searching). `ViewerState::set_filter` starts `spawn_filter` (chunked search through a read-tracking `FileSource`, `LineFinder` for line numbers) which sends batches about ten times a second; `poll_filter` appends them with `Arc::make_mut` and searches what a grown file gained. The filter bar keys tabs by `FilterTarget::{Editor, Viewer}`. Rules use `LogRules::look_text` on each drawn line.
- **Log highlight rules** go through the editor's `RowStyle` (background, per-span colours, `text_opacity`); the row style's background is painted over the current-line highlight.
- **Follow mode** (`external.rs`): the file's last 4 KB and size are remembered; a change that keeps them appends the new bytes with `Editor::append_unrecorded` (not an undo step: history change sets are extended with `ChangeSet::extend_base`, and the current revision is relabelled), holding back a partial UTF-8 character or a trailing CR. Anything else (shrink, other encodings) reloads. Followed files are checked 0.1 s after the first event, not postponed by later ones.
- **Undo across sessions**: `Buffer::saved_history(max)` / `restore_history`; `SavedHistory::check` replays every step against the text before it is accepted (a damaged file must not corrupt a document or panic). Files are `data/history/<sha256 of canonical path>.json` while the text is on disk, `backup-<snapshot id>.json` while unsaved; each records `sha256_hex` of the text it ends at and is restored only onto that text. Written by the worker (which hashes) on save, backup, close and exit; pruned to 300 at startup.
- **Huge files** (PLAN_v0.3.0 P7): files over `AppSettings::viewer_threshold_mb` (default 256, at most 1024 = `fileio::MAX_LOAD_SIZE`) open in a viewer tab, never in a `Buffer`. `BigFile` maps the file (the codebase's only `unsafe`) but only the lines on screen are read through the map, right after `refresh` checked the length each frame; the index builder and searches use positional reads, so a file truncated during a long pass gives short reads, not SIGBUS. What remains on Linux: a truncation between that check and the frame's reads of the visible lines (microseconds). Windows refuses to truncate a mapped file. The index stores the start of every 1024th line; `\n`, `\r\n` and a lone `\r` end lines and are never changed. `Searcher::new_raw` searches raw bytes (CRLF-aware anchors) through core's `ByteSource`, whose cursor never splits a UTF-8 sequence between chunks. The viewer draws `Shown` rows (all lines, or a filter's; see Log tools in the viewer). Viewers are in the session (`Session::viewers`, after the editor tabs in the layout's indices).
- **Settings** live in `AppSettings` (`settings.json`) and are applied in `apply_settings` only when they change. `keymap.json` entries replace or remove (`"command": null`) default bindings and apply on save.

## Not in scope (unless the user asks)

RTL/bidi text, proportional editor fonts and ligatures, virtual space, plugins/LSP/autocomplete, editing files over 1 GB, UTF-16 files in the viewer, full screen-reader support (a basic AccessKit node exists).

## Testing

- **Core**: unit tests plus proptest (`crates/ochrepad-core/tests/props.rs`): random action sequences, undo/redo identity, selection invariants, position round-trips. Keep generated text short (`short_text()`); long Replace/ReplaceAll replacements grew documents exponentially and hung debug runs.
- **fileio**: byte-exact fixtures in `tests/fixtures` (marked `-text` in `.gitattributes`; never let git or an editor touch their line endings). Bytes in must equal bytes out.
- **App**: one kittest file per feature in `crates/ochrepad/tests`. Harnesses use `.with_step_dt(1/60)` and `.with_max_steps(10_000)`, because highlighting runs on a wall-clock budget. The editor exposes an AccessKit node labelled `Editor: <file name>`, and the status bar shows `Ln x, Col y` as a label; tests find both by label. Mouse tests compute positions from the font's cell size (see `cell_pos` in `widget.rs`).
- **Snapshots** (`tests/snapshots/*.png`) use egui's built-in fonts only, so they don't depend on system fonts. After a visual change, regenerate them and **look at the PNGs** before committing. The kittest harness draws a transparent 8 pt margin around the app; real windows have none.
- Assert timings only in release builds (`cfg!(debug_assertions)` guards). File-watcher tests wait in real time (`wait_for` in `polish.rs`).
- To review a UI change at full size, render the app at `with_pixels_per_point(1.5)` after `ochrepad::fonts::install(&h.ctx)` in a throwaway test, save `h.render()` to the scratchpad, and look at it. Delete the test afterwards.

## Gotchas learned the hard way

- **egui_dock**: `retain_tabs` can leave a stale focused node and panic; remove tabs with `find_tab` + `remove_tab`. There are no hooks for tab-bar double-clicks or per-tab accents; both are done after `DockArea::show` using tab rects collected in `on_tab_button`.
- **Windows file URIs** need an empty host (`file:///C:/dir/x.png`); `file://C:/...` reads `C:` as a host.
- **`Color32` is premultiplied.** Build translucent tints with `from_rgba_unmultiplied` from straight RGB; a weak tint cannot be made strong again.
- **egui shortcut matching ignores extra Shift and Alt** (`consume_shortcut`), so Ctrl+Alt+F would also fire Ctrl+F. The app's fixed shortcuts skip events with an Alt they don't ask for. With Shift held, a digit key arrives as its symbol (`Alt+Shift+1` as `"!"`); the editor falls back to the event's `physical_key` for keymap lookups.
- **egui key names** are `"Down"`, not `"ArrowDown"` (`Chord::parse` accepts both). Menu items with shortcut text have accessibility labels like `"Undo Ctrl+Z"` (label, space, shortcut), so tests use `get_by_label_contains`.
- **Config dir**: the keymap file's folder may not exist on a first run; create it before saving there.
- **Deleted files cannot be canonicalized.** The watcher matches paths by canonical parent + file name (`watch_key`).
- **Python dictionaries**: the first key after a line-ending `{` is coloured as a plain string. This is a limitation of two-face's Python grammar under syntect (it cannot look past the line), not our highlighter.
- Git prints LF→CRLF warnings on commit (autocrlf); they are harmless.
